# 网格引擎评估：Gmsh 集成 vs 体素方案（T22 决策）

- 决策日期：2026-09-08
- 结论：**v1 保留体素方案为默认**；Gmsh（外部进程，GPL 隔离）作为质量升级路线，列为条件触发任务（真实求解跑通后启动）。
- 原型与解析器：已入库 `services/gmsh.rs`（msh v2.2 ASCII 读写 + 单测）；运行时对比待 gmsh 环境就绪后补测。

## 对比

| 维度     | 体素 + 5-四面体（现状）           | Gmsh Delaunay（候选）                                               |
| -------- | --------------------------------- | ------------------------------------------------------------------- |
| 边界贴合 | 阶梯近似（体素中心判定）          | 贴合 STL 表面 ✓                                                     |
| 单元质量 | 纵横比 ~1.0–1.7（规则网格理想值） | 取决于参数，通常更优                                                |
| 实现成本 | 已落地                            | 外部进程 + msh 转换（解析器已入库）+ 参数体系                       |
| 许可证   | 自研，Apache                      | GPL → 子进程隔离（与 T09 同模式，先例已验证）                       |
| 生态     | 自研维护                          | 工业级成熟、社区大、教程多（MIT 教学平台已验证 Gmsh WASM 路线可行） |

## 触发条件（满足其一即启动替换工程）

1. 真实求解跑通后，确认体素阶梯边界影响求解精度（对比 openInjMoldSim 官方 dogbone 结果）；
2. 出现需要贴合复杂曲面的真实制品需求。

## 已落地的原型资产

- `services/gmsh.rs`：msh v2.2 ASCII 解析（节点 / type-4 四面体 / 高阶跳过）与回写（体素网格 ↔ msh 往返一致性有测试）——未来无论选择哪条路线，该数据交换层直接复用。
