## 口径与改动

- **选择规则改为「一达到请求面积就停手」**：旧实现把半径内的面全部吃掉，再补到目标
  面积为止；半径内若有一个远大于浇口的面（真实件上单面 493 mm² vs 请求 50 mm²），
  入口就被放大成宽带（实测 1200 mm²）。现在从最近面起累积、达标即停，多吃的只有最后
  那一个面——可表达网格上偏差 ≤ 2 倍（回归测试用 4 mm 立方体 + 1 mm 体素 + r2 浇口锁定）。
- **保底至少一个面**：浇口小于一个单元时不能产出空 inlet（求解器会完全没有进料口），
  所以宁可取一个超标的面并告警。
- **不可表达判据**：实际 / 请求面积比 > 2 → `expressible = false`，生成明确告警
  （请求直径、实际面积、等效直径、倍数、最小入口面等效边长，并提示加密网格或加大浇口）。
  这就是 T72 现象记录里「等效 φ39 mm 的带状入口」的自动化版本——不再需要宿主侧手算。
- **回显落地**：`CaseReport`（inlet/vent/walls 面积 + 逐浇口回显 + 告警）→ CLI JSON
  `inlet` 字段与文本行；Tauri `CaseOutcome` → 流水线写入工艺 store（带 studyId，
  跨研究不复用）→ 工艺面板显示「请求 vs 实际」行与告警。
- **T62 提示改用有效面积**：工艺面板的填充工况校验优先用最近一次 case 回显的实际
  inlet 面积（网格真正表达出来的入口），没有回显时退回请求半径的等效面积。

## 处理记录

- **立即修**：删两条不可达分支；`min_face_area` 的 0 兜底加了「无边界面网格」用例
  锁定（该分支此前无覆盖）。
- **回流任务**：无新增。
- **接受并记录**：选择仍以「距离最近」排序（不按面积升序）——面积优先会把入口打散到
  半径各处，紧凑性对流动影响更大；仅在超标时告警而不改排序。另：`PatchAreas` 保留为
  内部结构（`CaseReport` 内联三个面积字段），case 字典不再需要单独的 PatchAreas 出口。
- **与 T74 的衔接**：T74 的浇口速度阈值（20 m/s）在 T72 前对真实件报出的是「名义速度
  被拉低」，现在面板的校验输入换成有效面积后，该提示与求解器实际入口条件一致。
