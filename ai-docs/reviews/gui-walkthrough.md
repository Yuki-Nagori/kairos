驱动方式：computer-use 以可访问性树（AX）驱动打包中的开发版应用
（`bun run tauri dev`，pid 变化即 Rust 改动触发重建）。本轮截图/坐标/键盘/滚轮
四条原生通道在**未签名开发包**上不可用（详见文末「驱动限制」），因此全部操作
经 AX 语义动作完成。

## 发现的问题与处置

1. **方案创建入口缺失（工作流断点）** —— T68，已修复并复测：新建工程自带
   `方案 1` 并选中；「＋ 新建方案」补齐创建入口与空态提示；模具网络面板的引导
   文案原先指向不存在的控件，一并改向。
2. **材料公式刷屏可访问性树** —— T70，已修复并复测：`LatexBlock` 按
   `role="img"` + `aria-label` 暴露，整窗 AX 节点 419 → 177，两个公式各占一个
   `image` 节点。
3. **术语「方案 / 研究」混用** —— 仅记录：面板标题、按钮与提示里两种叫法并存
   （见 T69）。

## 驱动限制（影响后续 GUI 自动化走查）

- `screenshot` 返回「无可用栅格」，`zoom` 报
  `capture_app: native capture returned no usable pixel-to-pointer rectangle`；
- 因此左键/滚轮的坐标目标、`type`/`key` 的应用级绑定一并被拒
  （`app_ref did not resolve to a unique live application`：开发包
  `bundle_id` 为空）；
- `AXScrollToVisible` 对已在视野内的元素是空操作，右列滚动位置无法改变 →
  折叠线以下的面板（工艺设置、作业面板）不可达。
- 结论：可访问性树驱动足以覆盖「可见即可操作」的界面，走查深面板需要
  **打包版应用（有 bundle id）**或先修可访问性树的滚动可达性。
