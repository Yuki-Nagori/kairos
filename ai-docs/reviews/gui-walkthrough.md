# GUI 走查报告（桌面应用可访问性树驱动）

驱动方式：computer-use 以可访问性树（AX）驱动 Kairos 桌面应用，必要时辅以
应用级键盘与显示级坐标。本轮走查暴露了 4 个**驱动侧**硬条件与 1 条桥的预算
限制，全部已定位到可复现判据；产品侧问题见 T68 / T70 / T71。

## 二、驱动侧的四个硬条件（缺一不可）

1. **应用要有 bundle id**。`bun run tauri dev` 跑的是裸二进制，`list_apps` 里
   `bundle_id: null` → 应用级键盘 / 滚轮 / 坐标一律被拒
   （`app_ref did not resolve to a unique live application`）。
   走查用打包版：`bun x tauri build --debug` → `target/debug/bundle/macos/Kairos.app`
   （`CFBundleIdentifier = com.yuki.kairos`），再 `open` 启动。
2. **窗口要在屏上**。显示器休眠时 `kCGWindowIsOnscreen = false`，原生输入被
   `reason=window_offscreen` 拒绝、截图也拿不到栅格。走查期间保持点亮：
   `caffeinate -u -d -t <秒>`（`-u` 点亮、`-d` 阻止再休眠）。
3. **显示级坐标点击落在最前面的窗口**。坐标派发走显示级事件，Kairos 不在最前
   就会点到别的应用（实测点到了 VSCode）。走查前把目标应用激活到前台。
4. **栅格坐标 = 整屏缩放到 1280 宽**（本机 1470×956 → 1280×832，比例
   `1280/1470 ≈ 0.8707`）。AX 树给的 bounds 是屏幕点，换算后再当坐标用；
   原生输入前需先 `screenshot` 刷新帧，否则报 `frame stale`。

## 三、可访问性桥的预算限制（本轮最硬的一堵墙）

- `main` 容器报 `showing 0-63 of 130 items`：**每个容器按 DOM 顺序只暴露前 63 条**；
- 滚动容器内元素在 AX 上的 y 是**内容坐标系**（滚下去后「方案摘要」的 y 变为
  −415），滚动不改变截断位置——**滚动无法**把第 64 条以后的面板带进树；
- 模具网络一张卡片就占 ~32 条（15 个 `input type=number`，每个在 AX 上约 5 个
  节点：输入框 + spinner + 上下按钮），工艺设置正好被截在门外；
- 可行手段：**把前面的长卡片折叠**。T71 把 UiCard 标题栏改成 `role="button"`
  （回车 / 空格可切、读屏可读），模具网络与运行时依赖开折叠 → 折叠后后续面板
  进入预算，可继续用 AX 精确驱动。
- 另一条路（不改产品）：显示级坐标 + 前台激活 + 滚轮盲点，代价是坐标要按
  0.8707 自己换算、每次动作前刷帧，且看不到栅格内容，脆弱。
