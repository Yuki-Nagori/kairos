## 布局与口径（定稿）

```
<文档目录>/kairos/<工程目录>/          # 工程目录 = 工作区根
  <用户命名>.kairos                    # 新建工程时可改文件名（默认 project.kairos）
  geometry/                            # 导入的原始几何（原样拷贝，重名加 id 前缀）
  mesh/<方案 id>/mesh.bin + mesh.json   # 体积网格 + 报告/参数清单
  cases/<方案 id>/                      # 求解 case（生成物，可重建）
  reports/                             # 报告输出目录
```

- **文档目录不硬编码**：macOS / Linux / Windows 与各语言下的目录名不同
  （`Documents` / `文档` / `Dokumente`），一律由 Tauri `document_dir()` 解析后传入 core；
  core 只做纯路径运算，测试用固定路径。
- **工作区判定**：工程位于 `<文档目录>/kairos/` 下的**子目录**（不是根目录本身）时，
  该子目录即工作区；其它位置（桌面散装文件、直接放在 `kairos/` 下）视为无工作区，
  数据留在应用数据目录（旧行为），UI 明确标注「散装工程」。
- **工程文件只存相对路径**：`geometry/<文件名>`、`mesh/<方案 id>/mesh.json`；
  换机器 / 换盘后仍可用（同架构）。
- **新建工程**：`<文档目录>/kairos/<工程名>/<用户文件名>.kairos`，创建即落盘并登记最近工程。
- **打开工程**：按引用读回几何（沿用工程里的 geometry id，使方案 / 网格引用天然对齐），
  再逐方案读回体积网格（缺文件不算错误，报告可重建）。
- **CLI**：`pipeline run --out-dir` 默认 `workspace/`，case 落在 `<out-dir>/cases/cli/`，
  JSON 输出同时给 `workspace` 与 `caseDir`。
- **报告**：工作区工程生成报告时直接写 `<工作区>/reports/<方案名>.html`（面板状态行给出
  绝对路径）；散装工程回退浏览器下载；写入失败（目录只读等）也回退下载，保证报告一定能拿到。

## 处理记录

- **立即修**：`Component::Prefix`（Windows 盘符）在 Unix 上无法构造，覆盖率门禁直接暴露；
  改为「路径含冒号即拒绝」的显式判定，跨平台语义一致且可测。`Component::RootDir` 分支
  被前置的 `is_absolute()` 判定覆盖，删掉。
- **消融抽查**：把 `workspace_root` 的「父目录必须是默认根的子目录」判定去掉（改回
  「有父目录即工作区」）→ `workspace_root_requires_default_root_subdirectory` 变红
  （直接放在 `kairos/` 下的工程被判成工作区）；文件级还原后复绿。
- **回流任务**：无新增。
- **接受并记录**：① 几何归档为原样拷贝（大 STL 会翻倍占盘），压缩 / 指纹去重按任务
  非目标推迟；② 求解作业脚本、结果回传路径未逐一改造——它们都以 `default_case_dir`
  为唯一入口，该函数已按工作区解析，故自动跟随；③ 工作区路径在工程树里是只读展示，
  点开目录（Finder / 资源管理器）属 UI 增强，随下次工程面板改动做。
