# 上游问题清单（moldingFoam / 求解侧）

本文件汇总 Kairos 侧**被上游能力或发版节奏阻塞**的事项，按「最影响我们排期」排序。
每条都带上我们已经做过的验证与证据，便于上游直接回答，不必来回追问。

维护方式：问题解决后从表中移除，并在对应任务的「进度与依赖」里记一条结论。

## 1. 发版节奏：046（并行死锁修复）与版本可预期性

- **现状**：046 上游已定位根因并修复（边界 patch 循环内归约 → 各 rank 归约次数不等），
  也加了回归用例；但我们消费的 bundle 仍是 v0.2.5（含该缺陷）。
- **我们的验证**：真实件（46.7 万面控制器支架）np=1/2 跑到 endTime（V/P 切换 1.0802 s、
  保压 59.3 MPa）；np=4 在第 1 个时间步后死锁（4 rank 常驻 CPU、无输出无报错），
  gdb 抓到的两组 rank 停在不同集合通信里，与 046 的结论一致。
- **需要上游**：下一个 release 的预计时间；以及 release 是否遵循语义化版本
  （我们按版本标记判断「VM 内环境是否需要重新部署」）。
- **影响**：T29 的真实件多进程验收、T83 的多腔填充验收都在等这一版。

## 2. 一维流道 / 降维网格的消费口径（T82 + T83 合并问题）

- **现状**：Kairos 侧已有两种降维表达——双域（表面三角形 + 一维梁）与中面（射线配对），
  流道单元在双域网格里就是梁单元。
- **需要上游**：求解器**能否消费一维流道 / 降维网格**；若能，接受什么形式
  （梁截面 + 等效阻力？还是要求流道也进体网格）；中面 / 双域 case 需要哪些额外字典项。
- **影响**：T83 的范围 1（流道几何进网格）与 T82（双域/中面求解消费）都停在这里。
  在此之前我们只做数据位与校验，**不推测 case 契约**——写进去没人读，等口径变了还要返工。

## 3. 多腔（多 inlet）的流量分配归属

- **现状**：Kairos 已能把每个浇口落成独立 inlet patch（`gate_portals` → 入口面选择，
  含实际面积、等效直径、面积比与「网格能否表达」判定）。
- **需要上游**：多腔场景下**流量分配由求解器按几何自动分配，还是 case 侧需要给出
  分配曲线 / 权重**？顺序填充（sequential）与平衡填充（balanced）是否作为求解器选项？
- **影响**：T83 范围 2（多腔分配判据）无法在 Kairos 侧独立定义。

## 4. release 是否提供校验值（SHA256SUMS）

- **现状**：上游 release 只有两个归档（`moldingFoam-v0.2.5-{amd64,arm64}.tar.xz`），
  没有校验文件。我们已做：下载后计算 SHA-256 落进应用清单（`ManifestEntry.sha256`），
  可跨会话核对同一文件是否被替换，供追溯。
- **需要上游**：是否可以在 release 附带 `SHA256SUMS`（或归档旁附 `.sha256`）。
- **影响**：有官方值后，我们能把「记录摘要」升级为「比对校验」，供应链完整性才算闭环。
  在此之前应用侧无法判断下载物是否被中间人替换。

## 5. 求解正常结束后的退出崩溃（malloc 告警）

- **现状**：bundle 环境在求解跑到 endTime 后、析构阶段偶发
  `malloc_consolidate(): unaligned fastbin chunk detected` 并带崩溃退出码。
- **我们的现状处置**：作业成败以「求解到 endTime + 输出完整」为准，退出码不单独作为判定依据
  （失败判定优先看求解器错误标记，见 `job_logic::job_failure`）。
- **需要上游**：这是否已知；若不修，是否会随 046 的版本一并变化。
- **影响**：自动化验收与 CI 只能绕过退出码，长期会掩盖真实的进程级问题。

## 6. 特殊工艺能力路线图（GAIM 气芯 / 纤维取向）

- **现状**：Kairos 侧已先行落地数据位——浇口/流道单元的介质标记（`RunnerElement.medium`，
  熔体/气体）已随工程文件往返保真；对称张量场（6 分量）读取通道已通。
- **需要上游**：①第二气体相（三相或独立场）的物性字典与入口 BC、气芯追踪与写出；
  ②取向张量求解与写出（以及 `filler` 相关关键字冻结口径）。
- **影响**：T89 第二步（GAIM case 跑通 + 气芯云图）与 T91 剩余（`a2` 张量消费）等这两项。
  数据位已备好，上游一就绪我们即可接 case 生成与结果展示。
