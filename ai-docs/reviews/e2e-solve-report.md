## 4. 上游（moldingFoam）缺陷与本轮结论

1. **v0.1.1 SIGILL**（v0.2.0 已修）：`libmoldingFoam.so` 含 M4 不支持的指令；
   v0.2.0 起正常迭代。
2. **退出期堆破坏**（v0.2.1 已修）：bundle 把同一求解模块打包成两份独立 .so
   （`libmoldingFoam.so` 新构建 + `libmoldingFoamSolver.so` 陈旧构建，均非符号链接），
   controlDict 的 `libs` 行与 foamRun 的模块探测各加载一份，运行日志出现
   18 条 `Duplicate entry … in runtime selection table`，退出析构时
   `malloc_consolidate` 堆破坏。A/B 判别：仅加载陈旧那份 → SIGILL(132)；
   把 `libmoldingFoamSolver.so` 改为指向 `libmoldingFoam.so` 的符号链接（只加载一份）
   → `exit 0`、无重复警告与堆报告。v0.2.1 已按此修复，本报告 §1 为复跑确认。
3. **CI 掩盖**（对方本轮自查发现并修复）：`scripts/run-solver-tests.sh` 曾用
   `foamRun … || true` 吞掉退出码，使「End 后崩溃」被判为全绿。

## 5. 真实 STL 一轮（Thingiverse 控制器支架，46.7 万面）

素材：`samples/stl/Bulbasaur Controller Stand - 7406183`（Thingiverse 用户 TriDimen，
CC BY-NC-SA；3MF 内含 5 个部件、466,988 三角面；转成二进制 STL 后导入，
包围盒 111.1 × 167.4 × 132.9 mm，三角面有向体积和 880.8 cm³）。`samples/` 已在
`.gitignore` 中，素材不随仓库分发。

导入与网格（Kairos 侧全部通过）：

| 体素尺寸 | 节点 / 四面体    | 生成耗时 | polyMesh 体积 | 相对真值 | 非正体积单元 | checkMesh |
| -------- | ---------------- | -------- | ------------- | -------- | ------------ | --------- |
| 5 mm     | 9,584 / 37,540   | 18 s     | 879.0 cm³     | 99.8%    | 0            | Mesh OK   |
| 4 mm     | 17,431 / 71,075  | 25 s     | 878.9 cm³     | 99.8%    | 0            | Mesh OK   |
| 3 mm     | 39,684 / 169,405 | 46 s     | 874.6 cm³     | 99.3%    | 0            | Mesh OK   |

即：百万面级 STL 的导入 + 体素化在体积保真（±0.7%）与网格质量（零负体积、
非正交 ~0、最大偏斜 0.25）上均达标，`write_poly_mesh` 的修复在真实复杂几何上
同样成立。

求解：**在固定填充分数处发散**，未能完成填充。

| 配置                                   | 发散时刻     | 发散时填充分数 | 发散前一步门控压力          |
| -------------------------------------- | ------------ | -------------- | --------------------------- |
| Q = 8.79e5 mm³/s（默认工艺，1 s 注射） | t ≈ 0.0134 s | ≈ 1.6%         | —                           |
| Q/4（流量降至四分之一）                | t ≈ 0.0537 s | ≈ 1.3%         | 16 MPa（前一输出 1.6e7 Pa） |

两条曲线的发散时刻与 1/Q 严格成比例，说明触发点是**空间事件**（熔体前沿到达
某个位置）而非时间步/流量问题；Courant 数在崩前一步由 0.117 直接跳到 3.3e7，
时间步塌缩到 1e-20 量级后全 NaN。日志中 t = 0 至 ~0.01 s 的迭代本身完全正常。

暴露的 Kairos 侧问题（记入待办，归 T07 浇口建模 / T55 浇口位置分析）：

1. **入口分带把阶梯侧向面当浇口**：真实零件的体素边界是阶梯面，底带内的入口
   面里 39% 的法向朝侧面（`nz > -0.5`），即熔体被从零件**外壁**注入，而不只是
   底面。样例方盒底面是平面，这个问题一直被掩盖。入口面共 382 个、面积
   45.6 cm²（其中侧向面约占四成）。
2. **默认工艺不适配真实件尺寸**：默认注射时间 1 s 对 880 cm³ 的件意味着
   880 cm³/s 的流量（样例方盒是 1 cm³/s 量级），量与真实工艺参数需要用户按
   件设置——CLI 目前只有默认工艺一条路径。
3. **真实件体素网格出现多个连通域**：本次 3 个（主域 37,530 单元 + 2 个各 5
   单元的游离块，源自体素化的孤立方块）。游离块不影响求解但应在网格生成阶段
   清理或提示，否则会被当成"零件的一部分"进入 case。
4. **求解侧需进一步定位**：发散点的压力场/相分布需要更密的写盘间隔
   （例：`writeInterval 0.001`）才能取出前一步状态；建议由 moldingFoam 侧
   结合上述入口面问题判断是"外壁注入造成的薄层高速"还是别的局部奇点。

## 6. 未决与遗留

- **前端视口/图表验证未做**：macOS 对 ZCode Computer Use 的「辅助功能 + 屏幕录制」
  未授权，桌面控制 fail-closed；需授权后再补这一轮（含结果截图）。
  结果目录已备好：宿主 `/tmp/kairos-e2e/box6-results`。
- **真实 STL 一轮未跑**：本机（含 `~/eit`、`~/Downloads`）无任何 STL/STEP 素材，
  需要一份真实零件几何后再补；届时同时验证 STL 导入 → 体素网格 → case → 求解。
- **样例 case 填充/稳定性问题：已闭环**（2026-09-13，上游 038 诊断 + T66 修复）：
  原因是「排气口为通用开放边界（密封逻辑不生效、入口流量 92% 逃逸）+ mm-as-m
  单位制」；T66 改成 SI 坐标/流量 + `moldingVent*` + `ventSealAlpha` 后，样例盒
  在 v0.2.2 上复跑为 V/P 切换 t≈1.16 s、t=2 s 填充 0.973、exit 0、无 NaN。
  剩余观察：填充分数先于压力触发切换时会有压力阶跃，薄通道几何（点浇口、
  真实件）在此失稳，求解器快速失败按设计报出——见 T66 任务文档「复验」。
- **（历史）样例 case 的填充窗口与边值问题**（交 moldingFoam 侧判断）：
  - 注射 1 s 的名义流量下，t=2 s 时前沿刚推进到顶层、体积填充约 80%，
    α 均值读数 0.75；顶层角部有残留空腔；
  - 把 endTime 拉到 6 s：**t ≈ 2.05 s 起发散**（`alpha`/`p_rgh` 全 NaN），
    发散前一步门控压力由 0.26 MPa 跳到 0.51 MPa；
  - 把 `maxAlphaCo` 由 0.1 收紧到契约 case 的 0.03：发散提前到 t ≈ 0.46 s
    （同刻物理量与 0.1 配置一致，说明是稳定性边界附近的敏感行为而非轨迹差异）；
  - 契约 case 在相同设置下跑到 t = 0.54 s 未见发散，可作为对照。
- Kairos 侧的「退出期崩溃兜底」已在 v0.2.1 复跑确认后撤除（其带有
  `decomposePar` 也打印 `End` 的误判风险），恢复严格判定。

## 7. 验收结论

- 样例立方体填充分析在真实求解器上**跑通到 endTime 且结果可读**：满足；
  定量「填满」受粗网格（10 单元高）与填充窗口（2× 注射时间）限制，见 §6；
- 真实 STL：导入 → 体素网格 → case 生成链路**通过**（体积保真 99.8%、Mesh OK、
  零负体积单元）；求解在真实件上暴露入口分带与工艺参数问题（§5），
  属待办范围而非链路缺陷，已归档；
- 发现的集成缺陷（6 项 Kairos 侧）全部修复并加回归测试；上游 2 项已由
  moldingFoam 修复并复跑确认；
- 依赖面板下载 / bundle 部署流程实测可用（v0.2.1 全链复跑）；
- 待补：前端展示截图（桌面控制权限未授权）、入口分带/工艺参数适配（§5 待办）。
