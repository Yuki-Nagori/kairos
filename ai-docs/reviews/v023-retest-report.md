# moldingFoam v0.2.3 复测报告（B / C 用例）

- 日期：2026-09-13
- 环境：release `v0.2.3`（arm64 bundle，20260913 资产）部署进 multipass `kairos`
  （Ubuntu 24.04，OpenMPI 4.1.6），`decomposePar -force` + `mpirun -np 4 foamRun
-parallel` + `reconstructPar`，case 由 Kairos 生成后**原参数复跑**
- 回传材料：`samples/cases/handoff-v023/`（log 全文、字典、场文件、故障前最后三帧）

## 结果

| 用例                        | v0.2.2 结局           | v0.2.3 结局                                                          |
| --------------------------- | --------------------- | -------------------------------------------------------------------- |
| B 点浇口样例盒（v3-point）  | t=1.1321 s non-finite | **通过**：跑到 endTime 2 s，`Phase-1 volume fraction 0.9983`，exit 0 |
| C 真实件 873 cm³（v3-real） | t=4.3409 s non-finite | **仍失败**：t=4.3463 s `The melt state became non-finite`            |

### 关键证据

- **B**：`pressureRamp = 0.05` 生效。V/P 切换点 t=1.1307 s（filled fraction
  0.9604、`p_gate = 2.97 MPa`、switchPressure 60 MPa）——与 v0.2.2 的崩溃时刻
  （t=1.1321 s）几乎是同一处：切换不再造成单步 ~57 MPa 阶跃后存活到结束。
  全程无 `freeze-off`、无 FATAL，仅一条 timePrecision 提升的非致命 Warning。
- **C**：切换点 t=4.3404 s（filled 0.9600、`p_gate = 5.44 MPa`）→ **6 ms 后**
  `Courant mean 51173 / max 2.0e8`、`deltaT = 5.07e-153`、T 与 p_rgh 残差 NaN
  → t=4.3463 s 各 rank 同时报 non-finite。50 ms 的 ramp 还没走完就已失稳，
  说明该用例不是被切换阶跃直接打死的。
- C 的密集写盘复跑（`writeInterval 1e-3` + `purgeWrite 4`）复现同一时刻，
  故障前最后三帧 4.344 / 4.345 / 4.346 已随包回传。

## 结论

1. `pressureRamp` 对「填充分数触发切换」的软化**确实有效**（B 从死到活，且正是
   旧崩溃点），上游该项修复在本链路确认；
2. C 仍在切换后数毫秒失稳，且与阶跃幅度无关（C 的 p_gate 更低、阶跃更小反而死）
   ——按通告「附日志即可」，材料已回传，请按新签名继续排查；
3. 未出现 `short shot` / `freeze-off` 提示，也未出现 fill velocity 超限告警；
4. Kairos 侧跟进项：T72（浇口入口面口径与有效面积回显）、T74（浇口速度阈值按
   SI 重标定到上游的 20 m/s）。

## 补充（同日，上游定论后按材料修正复跑）

上游用回传的三帧定论：C 是**冻死短射**类而非保压阶跃——case 里
`transport { mu 100; Pr 4; }` 让求解器反推的导热率 k = mu·Cp/Pr = 62500 W/(m·K)
（聚合物真值 0.2 量级），熔体入模即冻。Kairos 侧核实：生成器只采样了比热表，
**从未使用材料的导热系数表**，`mu / Pr` 是硬编码常数 → 已修（T76）。

复跑矩阵（均在同一 v0.2.3 环境、同一 case 上只改被验证的那一项）：

| 配置                                       | V/P 切换                    | 结局                                                                                                                                                                         |
| ------------------------------------------ | --------------------------- | ---------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| 原始（Pr 错）                              | t=4.3404 s，p_gate 5.44 MPa | t=4.3463 s non-finite                                                                                                                                                        |
| **仅修 k**（Pr → 1.388889e6，k 回到 0.18） | t=3.9184 s，p_gate 4.37 MPa | **填充变快**（不再冻），但切换后 **2.5 ms** 仍 non-finite（Courant 1.63e8、deltaT 1.2e-137）；**冻死守卫已开（418 K）且全程静默 → 熔体确实不再冻**，上游根因判断确认并被修掉 |
| 修 k + `pressureRamp 0.2`                  | t=4.0899 s，p_gate 4.37 MPa | **跑到 endTime 8 s**：Phase-1 体积分数 0.9957、保压段闸口压力 57.5 → 51.8 MPa 平滑跟随曲线、仅 1 条无害 timePrecision 警告、`reconstructPar exit=0`                          |

要点：

- **`pressureRamp` 对「材料修好之后」的 C 是有效的**：上游预期「更长的 ramp 不会
  解决、可做对照但预期同崩」，对照结果与该预期相反（0.05 s 死在切换后 2.5 ms，
  0.2 s 全程稳定）；
- 冻死守卫的键位已按上游源码确认：`freezeOffTemperature` / `freezeOffFraction`
  从 **moldingDict 顶层**读（`moldingDict.lookupOrDefault`）；日志回显里的
  `gateFreezeTemperature = -4.5036e+15` 是**另一个旧键**（闸口冻结封闸），
  不代表守卫未启用——排查时别被它误导；
- Kairos 侧生成器已随之改：`Pr = mu·Cp/k`（k 取材料导热表在熔温的插值）、
  写出 `freezeOffTemperature = b5` 与 `freezeOffFraction 0.01`、
  `packing { pressureRamp }` = 注射时间的 5%（夹 [0.05, 0.5] s；样例盒 0.05、
  真实件 0.2 两个点均已被上述复跑验证）；
- 浇口入口面口径（请求 8 mm、实际 1200 mm²）仍是 Kairos 侧待修项（T72），
  但已不再是 C 的阻塞点。

三帧与密集日志仍可复用；如需「材料修好后」的对照日志可再回传。
