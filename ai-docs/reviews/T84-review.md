## 决策与依据

- **压缩选 f32，不选 zstd**：基准显示解析文本（426 ms）才是加载大头，压缩的价值在
  传输与内存（80 → 40 MB）而非 CPU；f32 零依赖、容差有界（相对 2^-24），zstd 需新增
  依赖且对已结构化的浮点流收益有限。f64 通道保留（`ValueFormat::F64`）作为无损对拍路径。
- **缓存升级为 LRU + 值数预算**：条数上限对「几个大场」无效；预算按缓存内值总数计
  （默认 2e7 ≈ 160 MB），命中刷新最近使用，单场超预算时保底保留（否则缓存永远空转）。
  新增 `stats()`（命中/未命中）与 `usage()`（条数、值数）供验证与后续调参。
- **矢量通道独立**：矢量场不走标量缓存（用途不同），加载即回前端；标量/矢量载荷
  交叉解码明确报错，避免把 3 分量误读成 3 倍长度的标量场。
- **分块（子区间）懒加载未做**：消费端（云图 / 探针 / 派生）都需要完整向量，子区间
  加载没有落点；本轮按「按时间步请求 + LRU 命中不读盘」满足「切时间步不整场重载」。

## 处理记录

- **立即修**：`ValueFormat` 缺失时按 f64 读（旧载荷兼容）漏了测试覆盖，补「缺 format
  字段的历史载荷」用例；矢量 f64 值区分支同样补齐。
- **消融抽查**：把 `envelope` 里的值区长度校验去掉 → 「值区被截断」用例立即变红；
  还原后复绿（同轮还核对了 f32 编码确实把载荷减半——体积断言 + 实测 40/80 MB）。
- **回流任务**：无新增。
- **接受并记录**：ascii 解析 426 ms 是加载链路的真实大头，属上游产物（OpenFOAM 文本场）
  格式限制；若后续支持二进制场文件（`writeFormat binary`）再评估，不在本轮范围。
