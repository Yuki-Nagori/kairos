# T88 · 优化与自动化可行性（DOE 编排 / 工艺寻优）

- 日期：2026-09-13
- 状态：规划结论文档（**不做实现**）
- 输入：CLI（T32：`project / mesh / solve / results / pipeline run`，`--json`）、工作区布局
  （T75：case / 结果随工程走）、作业调度器（T10，VM 单实例串行）
- 结论摘要：**DOE 可在 CLI + 工作区之上叠加（前提是求解闭环稳定，即 T29）**；**工艺寻优
  需要一个目标函数与失败运行处置约定，属第二阶段**。两条路径都不需要新求解器能力

## 一、DOE / 正交试验编排

- **现状**：CLI 已能单次跑「几何 → 网格 → case → 求解 → 结果」并输出 JSON；工作区布局让每次
  运行的结果天然落在 `<工作区>/cases/<方案 id>/`。缺的只是「参数矩阵 → 批量提交 → 汇总表」。
- **资源约束**：求解走 VM 单实例（macOS Multipass / Windows WSL2），并行会互相抢算力与
  内存；Linux 本机通道（T85）同样建议串行。**结论：串行排队 + 每作业核数上限**，不做并发。
- **数据布局**：每次运行的 case 目录按「方案 id + 运行序号」隔离（如
  `cases/<方案 id>/run-003/`），与 T75 的工作区规则一致；汇总表落
  `<工作区>/doe/<批次>/summary.csv`（DOI 矩阵 + 每次运行的关键结果指标）。
- **参数维度**：熔体温度、模具温度、注射时间、V/P 切换体积分数、保压压力、保压时间、冷却
  时间、浇口直径（几何侧）；取值方式优先**正交表**（L9 / L16 起步，二维两水平的全因子在
  8 个维度上爆炸），拉丁超立方作为寻优阶段的采样器。
- **结果指标**：填充时间（`p` / `alpha.melt` 时间序列）、V/P 切换压力、最大注射压力、
  锁模力代理（入口压力 × 投影面积）、翘曲量（等 M4 有位移场后接）。
- **拆解**：一个任务（T92 `doe-orchestration`）。开工条件：**T29 真机求解闭环稳定**
  （同一 case 连续两次运行结果可复现）；否则 DOE 会在不可复现的基线上产出一堆噪声。
  验收：同一矩阵跑 3 组正交试验，汇总表含每次运行的目标指标与求解耗时，且失败运行被
  标记而不是静默丢弃。

## 二、工艺参数寻优

- **目标函数**：单目标起步（最大注射压力最小 / 翘曲量最小 / 填充时间最短），约束来自已有
  校验器：浇口速度 ≤ 20 m/s（T74）、浇口剪切速率 ≤ 5×10⁴ 1/s（T62）、填充覆盖率 100%
  （T59 预览可做零成本预筛）。
- **算法选型**：**网格搜索 / 正交表 → 高斯过程贝叶斯优化**（维度 ≤ 6、每次运行分钟级时，
  贝叶斯比网格省样本）；不做梯度类（求解器不可导、噪声大）。
- **失败运行处置**：非物理结果（NaN / 发散）按「高惩罚 + 重试一次」处理；连续 3 次失败即
  中止批次并报出失败参数点（**不允许静默跳过**——否则优化会收敛到「求解器没崩」的区域）。
- **资源与时间**：每次运行 1～10 分钟（VM 单实例），一个 50 样本的批次约 1～8 小时；界面
  需给出预计时长并按作业队列串行。
- **拆解**：一个任务（T93 `process-optimization`）。开工条件：DOE 汇总表可用（T92 之后），
  且至少有一个可量化的目标指标来自真实求解结果。
- **非目标**：云端并行 / 多机调度；代理模型（surrogate）精度承诺。

## 三、结论与落点

| 路径     | 结论                     | 依赖                    | 建档                              |
| -------- | ------------------------ | ----------------------- | --------------------------------- |
| DOE 编排 | 能（CLI + 工作区已就绪） | T29 求解闭环稳定        | T92（验收含失败运行标记）         |
| 工艺寻优 | 能（第二阶段）           | T92 的汇总表 + 目标指标 | T93（贝叶斯优先，失败点必须报出） |
| 并发调度 | **不做**（VM 单实例）    | —                       | 记录在案：串行排队 + 核数上限     |
