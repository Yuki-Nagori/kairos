# T01 · 性能预算与基准框架

- 阶段：M0 地基
- 依赖：无
- 优先级：P0（性能是一等约束，先立标尺再干活）

## 目标

把「注意性能」变成可度量、可回归的机制：先定义性能预算，再搭基准工具，让后续每个任务都有客观的性能标尺，而不是靠感觉。

## 范围

- 制定性能预算文档（数值为初版，允许后续修订但需说明理由）：
  - 视口渲染：≥100 万三角形下稳定 60 FPS；
  - 结果场加载：100 MB 结果首帧 ≤ 2 秒，期间 UI 主线程阻塞 ≤ 50 ms；
  - 求解调度：任意规模作业排队/运行期间 UI 掉帧为零；
  - 应用冷启动 ≤ 2 秒（到可交互）；
  - 网格生成：100 万四面体 ≤ 60 秒。
- 选型并搭建基准工具：前端渲染/UI 基准（可脚本化采样 FPS 与主线程长任务）+ Rust 侧 `criterion`；
- 制作标准基准资产：一组固定网格样例与结果样例，保证数字可横向比较；
- CI 中输出基准报告（先记录趋势，不作为卡点）。

## 非目标

- 不做任何具体功能的性能优化；
- 不做分布式/集群基准。

## 交付物

- `ai-docs/perf-budget.md` 性能预算文档；
- 可一键运行的基准套件（前端 + Rust）；
- 标准基准资产与 CI 基准报告。

## 验收标准

- 预算文档入库并列入 ARCHITECTURE 引用；
- 基准套件在干净机器上一条命令可复现全部数字；
- CI 每次主干构建产出基准报告。
