# T70 · 材料公式刷屏可访问性树（LaTeX 按单张图像暴露）

- 阶段：D0（平台底座 · 可访问性）
- 依赖：T04（材料库面板）、T26（工作台 UI）
- 优先级：**P3**（不阻塞功能，影响读屏与自动化驱动的可用性）
- 状态：**已完成**

## 目标

材料库面板里的公式（Cross-WLF 黏度、Tait PVT）在可访问性树上只占**一个**节点，
而不是把 MathML 的每个符号摊开成一串无意义节点。

## 问题（GUI 走查实测）

走查时按可访问性树驱动界面，材料库面板把整棵树刷爆：公式的 MathML 被逐符号
展开，「η」「=」「0」「+」「(」「)」各占一个节点，两个公式合计约 **255 个节点**，
占当时整窗 419 个节点的六成；材料参数（n / τ* / D1 …）这些真正有信息量的行
反而被挤到列表之外。

## 范围

1. `LatexBlock` 增加 `label` 属性，容器按 `role="img"` + `aria-label` 暴露：整段
   公式对辅助技术是**一张有名字的图**，名字由调用方给出；
2. 材料库两处调用传入公式名（「Cross-WLF 黏度模型公式」「Tait PVT 状态方程公式」）；
3. 组件测试补「按单张图像暴露」一条，其余用例补 `label`。

## 非目标

- 公式的 MathML→读屏逐符号可达（需要真正的数学无障碍通道，收益/成本另评）；
- 参数表的读屏顺序优化。

## 验收标准

- 组件测试断言 `role="img"` 与 `aria-label` 生效；
- 真机走查：材料库面板的公式在可访问性树上各占一个 `image` 节点，整窗节点数
  从 419 降到 177（已实测）；
- `bun run verify` 全绿。

## 当前实现边界

- 公式对读屏只给名字，不给内容——需要公式语义时以参数表为准（面板已列出全部
  数值）。
