# T72 · 浇口入口面口径与有效面积回显

- 阶段：B2（求解器 · case 生成质量）
- 依赖：T61（浇口几何落地）、T62（浇口速度提示）
- 优先级：**P2**（不阻塞求解，但让「浇口面积 / 注入速度」这一类判据失真）
- 状态：**待开工**

## 现象（v0.2.3 复测实测）

对同一批 case 量了 inlet patch 的真实几何（宿主侧解析 polyMesh）：

| case              | 请求浇口               | 实际 inlet patch                                                              |
| ----------------- | ---------------------- | ----------------------------------------------------------------------------- |
| 点浇口样例盒      | r = 1.5 mm（7.07 mm²） | 16 个三角形 · 15.5 mm² · 面心散布 1.4 mm（成盘 ✓）                            |
| 真实件（873 cm³） | 8 mm 浇口（~50 mm²）   | **7 个三角形 · 1200.3 mm²**（等效 φ39 mm）· 面心横跨 ~30 mm，单面最大 493 mm² |

真实件的实际注入面对应的名义速度只有 **0.18 m/s**（按 1200 mm² 折算），
而 8 mm 浇口应为 ~4.4 m/s——差 24 倍；即 case 的「浇口」实际是一条宽约 39 mm
的带状入口，而不是紧凑浇口。

## 影响

1. 上游按「浇口面积」判断面积/流量错配时拿到的是错误量级；
2. T62 的浇口速度提示用的是**请求半径**而不是**落进 case 的有效面积**，提示会
   与求解器实际拿到的入口条件不一致（案例里请求 8 mm、实际 39 mm）；
3. 宽入口带会把「浇口附近的高速/薄层」问题摊平或转移，掩盖真实的浇口效应
   （与真实件在保压切换后失稳的排查相关）。

## 范围

1. **portal 面积收敛**：按面积补齐的循环要处理「单个面就超过 π r²」的情形
   （当前会整面带入）；给出可取策略（选最小面 / 降级为最近面 + 告警 / 拒绝并
   提示加密网格）；
2. **有效面积回显**：case 生成结果（CLI JSON 与 App 的方案/校验面板）里带上
   `inlet_area_m2`、等效直径与「请求 vs 实际」偏差，T62 提示改用有效面积；
3. **网格耦合告警**：当目标尺寸远大于请求浇口半径时（面尺寸 >> r）明确提示
   「当前网格无法表达该浇口」；
4. 回归测试：小半径 + 粗网格、正常半径 + 细网格两组，断言有效面积偏差门槛。

## 非目标

- 浇口处的局部网格加密（属网格引擎能力，另行评估）；
- 流道系统的三维求解（当前仍是梁/面简化）。

## 验收标准

- 有效面积偏差（实际 / π r²）在可表达网格上 ≤ 2 倍，且不可表达时给出明确告警；
- CLI / 面板回显有效面积与等效直径；
- `bun run verify` 全绿。
