5. 批次会继续执行并写完所有参数点，但只要存在失败运行，CLI 最终以 `solver` 错误和非零退出码结束，避免自动化误判为成功。

### 复现边界

- Kairos 当前 case 生成器支持 STL、熔体温度、模具温度、注射时间、保压压力和保压时间；本轮 baseline 命令必须显式传入这些参数。
- 参考结果使用 Dual Domain，而 Kairos 当前使用体积网格；网格类型不同，压力和填充时间只能做趋势与量级对照，不能宣称逐点等价。
- 参考材料的完整 Cross-WLF、pvT 和热物性表需从 `result.txt` 的材料段逐项映射；缺失字段必须列为差异，不能用默认材料静默替代。

## CLI 入口

```bash
cargo run -p kairos-cli -- doe run \
  --factor '熔体温度=...' \
  --factor '注射时间=...' \
  --sample-box --out-dir <workspace> --solve
```

macOS 上 GUI 将 bundle 部署在 Multipass 的 `kairos` 虚拟机中；CLI 需显式复用该环境：

```bash
cargo run -p kairos-cli -- doe run \
  --factor '熔体温度=...' --factor '注射时间=...' \
  --sample-box --out-dir <workspace> --solve --vm
```

不带 `--vm` 时 CLI 只使用宿主机 PATH，不能看到 GUI 部署在虚拟机内的工具。

真实零件使用 `--stl <path>` 替换 `--sample-box`。运行前记录 `kairos-cli --version`、运行时版本、操作系统、架构和提交号。
