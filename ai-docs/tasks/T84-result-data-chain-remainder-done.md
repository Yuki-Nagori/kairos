# T84 · 大结果数据链剩余（分块 / 压缩 / 完整矢量场）

- 阶段：B3（后处理 · 数据链）
- 依赖：T51（二进制通道 + 有界缓存）、T13（结果模型）
- 优先级：**P2**
- 状态：**已实现**（2026-09-13）——值区 f32 截断（相对误差 ≤ 2^-24，f64 通道保留作
  无损对拍）、缓存 FIFO → LRU + 值数预算（2e7）、矢量场三分量通道贯通（读取 / 二进制 /
  命令 / 结果面板展示）；基准数字入 perf-budget。见
  [T84 评审](../reviews/T84-review.md)

## 目标

把大结果后处理闭环：按需分块加载、可选的取值范围压缩、完整矢量场（不只模量）。

## 现状（T51 的实现边界）

- 场加载走二进制 IPC 通道（f64 定宽 LE 值区 + JSON 元数据），带 FIFO 有界缓存
  （容量 8，非 LRU）；
- 值**未压缩**——T51 明确「值域差分 / 压缩（f32 截断或 zstd）待基准数字支撑后决策」；
- 矢量场多数场景取模量展示，完整三分量未贯通；
- 研究结果与工程的持久关联由 T75（工作区）承接。

## 范围

1. **基准数字**：大结果（≥1e7 值）的加载时延、内存峰值、解码耗时基线；
2. **按基准决策压缩**：f32 截断 / 值域差分 / zstd 三选一或多选，落地解码路径与容差说明；
3. **分块懒加载**：按时间步或分块请求，缓存策略由 FIFO 升级为 LRU / 加权；
4. **完整矢量场**：三分量贯通到视口与派生算子（接 T31/T44）。

## 非目标

- 结果文件格式的求解侧改造（上游产物不动）；
- 远程 / 流式结果服务。

## 验收标准

- 有基准数字支撑的压缩方案落地，解码与容差有测试；
- 大结果的内存峰值受控（目标由基准定），切时间步不整场重载；
- 完整矢量场可用于派生算子与展示；
- `bun run verify` 全绿。
