# T19 · GPU 计算基础设施（wgpu 跨厂商层）

- 阶段：M4 后处理与体验（基础设施，宜早启动）
- 依赖：无（可与 T01 并行）
- 优先级：P0（用户明确要求：GPU 辅助计算必须覆盖 NVIDIA / AMD / Intel / Apple 四类显卡）

## 目标

建立全应用统一的 Rust GPU 计算抽象层：基于 **wgpu** 一套代码覆盖四类显卡——
NVIDIA / AMD / Intel 走 Vulkan 或 DX12，Apple 走 Metal。后处理以 GPU 为运行前提；
GPU 不可用或初始化失败时必须明确报出“不支持”，不再提供 CPU 运行时回退。Rust
计算 device 与 WebView 渲染 device 不能共享资源，只能通过数据契约协作。

## 当前实现边界

当前仅有 Rust 侧适配器枚举、厂商名映射和少量 compute 原型。尚无多 GPU 选择、
显存预算、前端诊断页、三端兼容矩阵或渲染设备管理；GPU 测试还错误地假设所有
门禁环境都存在适配器。它们是后处理 GPU 必需策略下必须补齐的验收工作，而不是
已完成的基础设施。

## 范围

- 适配器管理：枚举所有 GPU、能力探测（特性/限制/显存）、厂商识别（NVIDIA / AMD / Intel / Apple，含 Intel 核显与 Arc 独显区分）；
- 设备选择策略：多 GPU 机器（如 Intel 核显 + NVIDIA 独显）的手动选择 UI 与自动推荐；
- CPU 参考实现：每个 GPU 算子保留 CPU 对拍实现，仅用于单元测试、离线诊断和
  数值一致性验证，不得作为产品运行时回退；
- 显存管理：预算与水位监控，超限策略（Intel 核显与共享内存设备的保守上限）；
- 厂商兼容矩阵：四厂商 × 主流驱动组合的实测清单，已知问题（老驱动 Vulkan 支持差异、Apple Metal 特性限制）的规避与降级开关；
- 诊断：诊断页展示当前使用的 GPU、后端（Vulkan/Metal/DX12）、显存占用（衔接 T09 诊断页）。

## 非目标

- CUDA / oneAPI / OpenCL 等单厂商或非统一技术栈（红线，禁止引入）；
- 多 GPU 并行拆分单个计算任务；
- 求解器内核的 GPU 化（OpenFOAM 7 无 GPU 路线，远期独立评估，见 T09 非目标）。

## 交付物

- Rust `wgpu` 设备管理模块与前端渲染能力探测；二者以二进制结果数据契约衔接，
  不承诺共享 device；
- 能力探测命令与诊断 UI 接入；
- 厂商兼容矩阵文档（实测结果持续更新）；
- CPU 参考实现与 GPU/CPU 一致性测试骨架。

## 验收标准

- 四类显卡（NVIDIA / AMD / Intel / Apple）实测：设备正确识别、后端按预期选择（Apple→Metal，其余→Vulkan/DX12）；
- 禁用 GPU（或驱动初始化失败）后，后处理入口明确显示为不受支持，不会静默走 CPU；
- 双显卡笔记本可选择计算所用 GPU，选择被记住；
- 显存超限时有明确的拒绝、分块或降低精度策略，而不是崩溃或驱动重置。
