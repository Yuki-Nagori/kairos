# T69 · 术语统一：「方案 / 研究」混用收口

- 阶段：D0（平台底座 · UI 一致性）
- 依赖：T68（方案创建入口，工作流断点已修）
- 优先级：**P3**（不阻塞功能，属可读性与可发现性问题）
- 状态：**待开工**

## 目标

同一对象（`Study`）在界面上只用**一个**中文词，消除「方案 / 研究」并存带来的
「这是两个东西吗」的疑问。

## 现状（GUI 走查记录）

- 称「方案」：工程面板（方案层 / 切换到方案）、方案任务、方案摘要；
- 称「研究」：材料面板按钮「用于当前研究」、工艺面板（作用于活跃研究 /
  校验并应用到研究）、模具网络面板引导语、报告面板、以及 store 与 core 的错误
  文案（「请先创建或选择一个研究。」「研究名称不能为空。」）；
- 计数：`src-web` 里「研究」约 55 处、「方案」约 31 处（不含测试）。

## 范围

1. 选定唯一术语（倾向**方案**：三个最显眼的面板已在用，且「方案任务」这类
   复合词已成体系）；
2. 统一 `src-web` 用户可见文案（面板标题、按钮、提示、任务清单提示、面板内
   notice）与 `kairos-core` 的用户可见错误文案（`models/project.rs` 的 add_study
   校验、`services/project.rs` 的 validate）；
3. 测试同步：前端涉及文案的断言、Rust 单测错误文案断言；
4. 若术语要覆盖代码标识符（如 `activeStudy` 的注释措辞），保持标识符本身
   （`Study` / `study`）不变，只改自然语言文案。

## 非目标

- 重命名 DTO 字段或 IPC 命令名；
- 中英文对照表之类的文档工程。

## 验收标准

- 全仓用户可见文案不再出现「研究」；
- `bun run verify` 全绿（含注释规范门禁）。
