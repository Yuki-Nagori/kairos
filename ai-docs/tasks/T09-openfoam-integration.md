# T09 · OpenFOAM 运行时与 openInjMoldSim 集成

- 阶段：M3 求解
- 依赖：T06（3D 网格）、T08（工艺设置）
- 优先级：P0（全计划的核心与最大风险项）

## 目标

把 GPL 求解器 openInjMoldSim（OpenFOAM 7）作为**独立子进程**接入 Kairos：生成 case、驱动求解、回收进度与日志。用户按一下「求解」，剩下的由 Kairos 完成——这正是把作者口中"对工业使用极不方便"的研究工具产品化的核心价值。

## 范围

- 许可证合规结论（先做，阻塞后续）：GPL-3.0 下子进程 + 文件交换方式的边界文档化；本仓库不出现任何 GPL 源码或头文件展开物；
- 运行时获取策略：OpenFOAM 7（.org）+ 编译好的 solver 的获取方案——捆绑（分平台）或首次引导安装，给出取舍与实现；
- Case 生成器：Kairos 的网格/材料/工艺/水路数据 → 标准 OpenFOAM case 目录（`0/`、`constant/`、`system/`，含 decomposeParDict 并行参数映射到用户核数）；
- 子进程管理：`AllMesh`/`AllRun` 生命周期、stdout/stderr 流式解析（时间步、库朗数、残差）→ Channel 进度、优雅终止与强杀兜底；
- 环境探测：OpenFOAM 是否可用、版本是否匹配、诊断页展示；
- 官方 dogbone 样例作为内置测试资产。

## 非目标

- 修改/分叉求解器源码；
- 求解内核 GPU 化（OpenFOAM 7 无 GPU 路线；GPU 辅助边界见 T19/T20）；
- 翘曲（Warpage）与纤维取向分析（求解器未覆盖，远期评估）；
- 远程/集群求解。

## 交付物

- 合规结论文档（ARCHITECTURE 引用）；
- core/适配层的 case 生成器、进程管理器 + 单测（用样例 case 断言生成的文件内容）；
- 运行时探测命令与诊断 UI。

## 验收标准

- 在装好运行时的机器上，由 Kairos 端到端驱动 dogbone 样例完成填充求解；
- 取消求解后 3 秒内无残留进程；
- 生成的 case 可被原生 OpenFOAM 工具链直接接受（用官方脚本复核）；
- 仓库审计确认零 GPL 代码进入；
- 核数映射正确（如 8 核机器生成 8 子域并行）。
