# T75 · 工作区布局（工程自包含：几何 / 网格 / case / 结果随工程走）

- 阶段：D0（平台底座 · 工程与数据布局）
- 依赖：T03（工程模型与持久化）、T06（体积网格）、T09–T11（求解集成）、T68（工程 / 方案工作流）
- 优先级：**P1**（越晚改，「数据在应用数据目录」的假设越多；当前无存量，切换成本最低）
- 状态：**待开工**（布局已定，见下）

## 目标

工程变成一个自包含目录：拷走一个目录 = 拷走整次分析（几何、网格、case、结果、
报告），换机器可用；机器级资源（求解环境 bundle、自定义材料、最近工程）不重复携带。

## 现状（已按代码核实）

- `Project` DTO（schema v4）只有 `schemaVersion / id / name / createdMs / updatedMs /
studies`，**没有任何几何或网格引用**（`models/project.rs` 与 `src-web/types/index.ts`
  双端一致）；
- 导入的几何与生成的网格只活在会话内存（按 geometry id 引用），**重启即失**——重开
  工程只剩研究 / 工艺配置，必须重新导入并重新划网格；
- case 目录 = `app_data_dir()/cases/<studyId>`（`src-tauri/commands/project.rs::
default_case_dir`），与工程文件位置无关，结果回传也落在那里；
- 机器级数据与工程数据混在同一层：`downloads/`（bundle 解压后约 700 MB）、
  `custom-materials.json`、`recent-projects.json`；
- 用户可见后果：不知道东西在哪、工程不可分享 / 备份、删除工程会留下孤儿 case。

## 布局（定稿）

```
<workspace>/
  project.kairos        # 结构 + 相对路径引用
  geometry/             # 导入的原始几何（原样拷贝，保留来源文件名）
  mesh/<studyId>/       # 体积网格（节点 / 单元 / 表面 + 生成参数）
  cases/<studyId>/      # 求解 case（生成物，可重建）
  results/<studyId>/    # 回传结果（派生数据，可重建）
  reports/              # 生成的报告
```

边界与规则：

- 机器级仍留应用数据目录：`downloads/`、`custom-materials.json`、
  `recent-projects.json`、VM 内 `~/moldingfoam-env`；
- 工程文件**只存相对路径**（绝对路径换机 / 换盘即失效）；
- `mesh/`、`cases/`、`results/` 缺失不算错误——它们由「几何 + 参数」确定，可重建，
  界面提示「可重建」而不是报错。

## 范围

1. **工作区根**：不加新 DTO 字段，由「工程文件所在目录」推导（`project.kairos` 的
   父目录）；散装 `.kairos`（旧行为）继续可打开，视为「无工作区」，保存时提供
   「转为工程目录」；
2. **几何落盘**：导入时把源文件拷进 `geometry/`，工程里存相对路径；打开工程时按需
   重载（Rust 侧仍按需入内存，不常驻）；
3. **网格落盘**：生成后写 `mesh/<studyId>/`，打开工程时可直接载入视口；
4. **case / 结果路径**：`default_case_dir(workspace, studyId)` →
   `<workspace>/cases/<studyId>`；无工作区时回退应用数据目录（旧行为保持可用）；
   作业脚本、结果回传、结果面板扫描随之改口径；
5. **报告**：输出目录默认 `<workspace>/reports/`；
6. **界面**：工程名旁显示工作区路径（可点开）；「另存为」→「另存工程目录」；
7. **CLI**：`pipeline` / `solve` 的 `--out-dir` 语义与工作区布局对齐（缺省 = 当前
   目录下的同名工作区）；
8. 文档与状态：architecture-status、任务索引、timeline。

## 非目标

- 多工程浏览器 / 最近工程界面重做；
- 云同步、网络盘并发锁；
- 把求解环境 bundle 或自定义材料搬进工作区（机器级资源）；
- 工程文件的增量 / 压缩存储（几何按原样拷贝，大 STL 会翻倍占盘，压缩另评）。

## 验收标准

- 新建 → 导入几何 → 划网格 → 生成 case → 求解 → **重启应用** → 打开工程目录：
  几何与网格直接可用，case 与结果都在目录内；
- 整个工作区目录拷到另一台机器（同架构）→ 直接可用；
- 删除工作区目录不影响其它工程；应用数据目录不再随工程增长（bundle 除外）；
- 旧散装 `.kairos` 可打开（无工作区模式）并能一键转为工程目录；
- DTO 双端镜像 + 契约测试、路径改动测试齐全；`bun run verify` 全绿。

## 当前实现边界

- 工作区根由工程文件位置推导，不支持「工程在别处、数据在工作区」的分离配置；
- 几何原样拷贝（不压缩、不指纹去重）。
