# T10 · 求解作业调度器

- 阶段：M3 求解
- 依赖：T09
- 优先级：P0

## 目标

让多个求解任务有序、可控、可观测地运行：作业队列、并发控制、进度与日志的统一观测点，并保证**任何求解负载下 UI 都不掉帧**。

## 范围

- 作业生命周期状态机：排队 → 运行 → 完成 / 失败 / 已取消，状态持久化（随项目保存）；
- 并发策略：按物理核数与内存水位决定同时运行的作业数，队列顺序可调；
- 进度聚合：每个作业的进度百分比、当前时间步、估计剩余时间；
- 日志观测：实时日志流（Channel）、历史日志回放、错误行高亮；
- 取消与清理：取消作业 → 终止进程组 → 清理临时 case；
- 失败呈现：非零退出/求解发散的可读归因（区分环境问题与数值问题）。

## 非目标

- 远程/分布式作业；
- 断点续算（接口预留，不实现）；
- 优先级抢占。

## 交付物

- core 调度器 + 单测（状态机全迁移路径覆盖）；
- 命令层（提交/取消/查询）与作业面板 UI（列表 + 详情 + 日志）；
- 作业历史存储。

## 验收标准

- 同时运行 2 个作业并继续操作界面，UI 主线程阻塞 ≤ 50 ms（对齐 T01 预算）；
- 取消排队中与运行中的作业均即时生效且无孤儿进程；
- 作业失败后能从日志定位到首个发散时间步；
- 状态机非法迁移（如从完成到运行）被单测证明不可达。
