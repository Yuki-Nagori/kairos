# T68 · 方案创建入口缺失（新建工程自带默认方案 + 工程面板「＋ 新建方案」）

- 阶段：D0（平台底座 · 工程 / 方案工作流）
- 依赖：T03（工程模型与持久化）、T07（方案承载浇口 / 水路单元）
- 优先级：**P1**（工作流断点：无方案时材料 / 工艺 / 浇注系统 / 求解全不可达）
- 状态：**已完成**（GUI 走查实测发现 → 修复 → 复测）

## 目标

新建工程后可以直接开工：工程自带一个默认方案并成为活跃方案，工程面板提供
「＋ 新建方案」入口（含空态提示），不含方案的旧工程也能就地补上。

## 缺陷（GUI 走查实测）

按「新建项目 → 导入样例 → 生成网格 → 材料面板「用于当前研究」」走查时，
材料登记没有任何可见变化，状态栏给出「请先创建或选择一个研究。」：

- `file.new` → `newProject` 建出的工程 `studies` 为空，且不设置活跃方案；
- 工程面板的方案层写作 `v-if="studies.length > 0"`，**全应用没有任何新建入口**
  ——store 里的 `addStudy` 只有单元测试在用，用户无路可走；
- 模具网络面板还写着「请先在上方项目栏选择或创建一个研究。」，指向一个并不
  存在的控件；
- 材料 / 工艺 / 浇注系统 / 求解作业都以活跃方案为编辑目标，因此整条工作流在
  第一步就断掉（「提交求解作业」恒为禁用）：新建项目后「方案任务」永远停在
  「选择材料」未完成。

## 范围

1. **core**：`services::project::create` 建工程时自带默认方案
   （`DEFAULT_STUDY_NAME = "方案 1"`），GUI 与 CLI（`kairos project new`）行为一致；
2. **store**：新增 `syncActiveStudy` 兜底——装载工程后原选中项不在则落到首个方案
   （新建与打开两条路径都调用），空方案工程不再停在「无活跃方案」；
3. **工程面板**：方案层改为「有工程即渲染」，头部加「＋ 新建方案」（默认名
   `方案 N`，N = 已有方案数 + 1），无方案时给空态提示；模具网络面板的引导文案
   改为指向该入口；
4. 文档与索引：architecture-status 的 D0 条目、任务索引、timeline。

## 非目标

- 方案的重命名 / 删除 / 复制；
- 多方案并行求解与结果对比；
- 面板文案里「方案 / 研究」混用的统一（另行收口，见 T69）。

## 验收标准

- 新建工程 → 工程面板即显示活跃的「方案 1」，材料「用于当前研究」登记成功
  （方案任务第 2 步出现 ✓）；
- 「＋ 新建方案」在任意时刻可补方案，新方案立即成为活跃方案；
- 打开不含方案的旧工程：给空态提示且一键可补；
- core 行覆盖 100% / 前端逻辑层 100%，`bun run verify` 全绿。

## 当前实现边界

- 方案名是自动序号（`方案 1` / `方案 2`…），暂不支持重命名（见非目标）；
- 方案只在内存里编辑，落盘仍走保存 / 另存为。
