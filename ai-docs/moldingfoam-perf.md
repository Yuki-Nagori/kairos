# moldingFoam 版本性能记录

按 **moldingFoam（上游求解器）版本**记录性能与收敛行为，供上游迭代后做同口径对比。

与 [perf-budget.md](perf-budget.md) 的分工：那里是 **Kairos 自身**的性能预算（渲染 / 网格 /
后处理算子的验收标尺）；这里是**外部求解器**的逐版本实测。

**规则**：升级 bundle 版本、或改动求解链路口径（case 生成、并行核数、`endTime`、环境布局）后，
在「记录」一节**追加一条**，不要改写已有条目——同版本的多次测量才是判断「这次变慢是上游还是
我们」的依据。

## 速览

- **先读这一条**：现有 v1.0.0 数字是在「部署标记 = v1.0.0」的环境下测的，但事后核对发现
  实际加载的求解器库是**源码重建**的那份，不是 v1.0.0 归档里的库——所以它们按
  「v1.0.0 环境（库为源码重建）」读，**不能当作制品口径**。依据见
  [v1.0.0 这批数字跑的是哪个库](#v100-这批数字跑的是哪个库)。
- 要**对比版本**：看「记录」。
- 要**新增一条**：先看「测量协议」——缺环境身份（尤其库 sha256）的耗时数字不予收录。
- 之所以要为一个小版本单独建文档：上游只改求解器默认值不报错，墙钟与收敛路径就会悄悄变；
  而**标称版本号 ≠ 实际加载的二进制**这件事我们已经真实踩到过一次。

## 记录

### v1.0.0

**测量日期** 2026-09-15。**环境** kairos 虚拟机（Ubuntu 24.04、`nproc` = 5、11 GiB）。

#### v1.0.0 这批数字跑的是哪个库

部署标记是 `v1.0.0`，但加载路径上生效的是另一份库：

| 实体                            | sha256 前缀 | 状态                                  |
| ------------------------------- | ----------- | ------------------------------------- |
| 归档包内 `libmoldingFoam.so`    | `76e5e5e3…` | 已改名 `.disabled-bundle`，不参与加载 |
| 源码重建的 `libmoldingFoam*.so` | `7d4c7965…` | 位于 `~/OpenFOAM/ubuntu-14/…`，生效   |

原因：`source …/moldingfoam-env/openfoam14/etc/bashrc` 之后，`FOAM_USER_LIBBIN` 指向**源码重建树**、
`FOAM_LIBBIN` 指向已禁用的部署树，加载取到前者。

→ 因此本条记录的口径写作「**v1.0.0 环境（库为源码重建）**」。加载路径的不变式（每个 dlopen 名字
只能有一个可达实体、`<名字>Solver.so` 必须是同目录相对符号链接）与核对过程见
[reviews/solver-lib-duplication-report.md](reviews/solver-lib-duplication-report.md)、
[T97](tasks/T97-solver-lib-duplication-guard.md)。

#### 墙钟 vs 网格规模

样例立方体 10 mm、注射 1.0 s、`endTime` 2.0 s、`mpirun -np 4`。

| 目标尺寸 | 网格规模      | 求解墙钟                  | 负载             |
| -------- | ------------- | ------------------------- | ---------------- |
| 2.0mm    | 625 四面体    | 12.6 秒                   | 虚拟机空闲       |
| 1.0mm    | 5,000 四面体  | 32.0 秒                   | 虚拟机空闲       |
| 0.4mm    | 78,125 四面体 | 未单独计时（见端到端项）  | 虚拟机空闲       |
| 0.5mm    | 40,000 四面体 | ≥ 20 分钟（未跑完即中止） | **另有并发求解** |

对应的收敛与守恒证据：

- **625**：退出码 0；
- **5,000**：退出码 0；V/P 切换 0.9624 @ t = 1.0419 s；质量预算残差 −7.2e-07 kg；
- **78,125**：退出码 0；2,220 步到 `endTime`；残差 3.93e-07 kg；21 个时间目录；T@t=2 = 384.7 / 462.9 K；
- **40,000**：未跑完，无证据。

读法（别简化成「越细越慢」）：

- 墙钟 ≈ 单元数 × 步数 × 每单元每步开销，三项同时变——细化既抬高单元数，又压小 Co 数受限的
  时间步长、步数跟着涨；
- 实测每单元每步开销：625 四面体 9.7 µs、5,000 四面体 2.3 µs。小网格上 MPI 与每步固定开销
  占比大，故 625 → 5,000（单元 ×8）墙钟只涨 2.5 倍，是**次线性**；
- 0.5 mm 那行叠加了并发负载，按单元 × 步数外推到空闲机器约 **4–6 分钟**（待复测替换）。

#### 其他数字

| 项                      | 实测                                 |
| ----------------------- | ------------------------------------ |
| `vm_deploy_bundle` 部署 | 11.6 秒（含解压与校验）              |
| 环境链路端到端（L2）    | 17.9 秒（生成 → 求解 → 回传 → 读场） |

bundle 资产（arm64）sha256：`ecbd8b09a20879bf7b7866ee0e7c039b3d8276d9163a7769c9cb6c34c8525bc1`。

同版本上游自测：其真实件 `np4` 跑到 `endTime` 为 **5,069 步**，且 1 / 2 / 4 进程结果一致
（046 并行死锁修复的验收）。我们侧同口径件缺失，故验收口径定为「同规模 + 全链路」。

### v0.2.5 / v0.2.1

这两版只留下**收敛行为**，没有可比墙钟——当时的测量没记环境身份与负载条件，正是本协议要固定的东西。

| 版本   | 样例盒填充（t=2 s）    | V/P 切换压力 | 真实件                        |
| ------ | ---------------------- | ------------ | ----------------------------- |
| v0.2.1 | 0.751                  | 0.15 MPa     | t ≈ 0.0134 s 即发散           |
| v0.2.5 | 0.990                  | 57.6 MPa     | 跑满 `endTime`                |
| v1.0.0 | 0.9731（单位制修复后） | —            | 上游自测 np4 跑满（5,069 步） |

v0.2.1 另有两项已知问题，均已由上游修复：退出期崩溃（`malloc_consolidate` + 152 条
`Duplicate entry`）与 SIGILL；修复形态是把 `libmoldingFoamSolver.so` 改成指向
`libmoldingFoam.so` 的**相对符号链接**。详见 [reviews/e2e-solve-report.md](reviews/e2e-solve-report.md)。

## 测量协议

每次测量记下下列字段。缺任一项则该次数据只作内部参考、不进对比表——没有环境身份的耗时数字
无法归因，这正是本文档存在的理由。

| 字段                | 记什么                                                         |
| ------------------- | -------------------------------------------------------------- |
| 上游版本            | 部署标记（`~/.kairos-release-tag`）                            |
| **求解器库 sha256** | 加载路径上**实际生效**的那份，及 `FOAM_USER_LIBBIN` 指向哪个树 |
| bundle 包 sha256    | release 资产摘要（下载校验用的那个值）                         |
| 环境规格            | 虚拟机 `nproc`、内存、镜像版本                                 |
| case 口径           | 节点 / 四面体数、目标尺寸、`numberOfSubdomains`、`mpirun -np`  |
| 工艺口径            | 注射时间、`endTime`、材料                                      |
| 负载条件            | **虚拟机是否空闲**（并发求解会显著抬高墙钟）                   |
| 墙钟与步数          | 墙钟（秒）、推进步数、退出码                                   |
| 收敛与守恒证据      | V/P 切换时刻与填充率、质量预算残差、FATAL / NaN 计数           |

库身份要这样读（别只看文件名——加载路径靠符号链接成型）：

```bash
cat ~/moldingfoam-env/.kairos-release-tag          # 部署标记
source ~/moldingfoam-env/openfoam14/etc/bashrc     # 之后才知道 FOAM_USER_LIBBIN 指向哪个树
echo "USER=$FOAM_USER_LIBBIN"; echo "LIB=$FOAM_LIBBIN"
find ~ -name 'libmoldingFoam*' -printf '%y %s %p\n'   # 注意 -type f 会漏掉符号链接
sha256sum "$FOAM_USER_LIBBIN"/libmoldingFoam*.so
```
